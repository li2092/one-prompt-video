# 三条参考生产线

主生产线（填 `video.json`）做的是版式类的短片。下面三条做它做不了的画面：有角色的叙事短片、3D 场景、自然风景。它们没有现成版式，画面要自己写代码，每条给了一个能跑的最小工程和要守的做法。

先判断该不该走这里：

- 用户明确要这类画面，主生产线又确实做不了，才走。
- 这三条都要自己写几百行画面代码，并且对着出来的图反复改。写不了、看不了图的，如实告诉用户这类片子做不了，不要硬做。
- 只是想给版式片加一场特别的画面，用 `custom-scenes.md` 就够了，不用走这里。

| 生产线 | 做什么 | 最小工程 | 不适合 |
|---|---|---|---|
| Canvas 2D 短片 | 风格化的 2D 叙事：卡通角色、剪纸、拼贴 | `SKILL/assets/pipelines/canvas2d/` | 写实的人和环境 |
| three.js 场景 | 硬表面的 3D 场景：产品、建筑、车辆、机械 | `SKILL/assets/pipelines/threejs/` | 写实的人物；有机形体 |
| 全屏着色器 | 没有人工物的自然景：山、云、天空、日出 | `SKILL/assets/pipelines/shader/` | 有建筑、道具、角色、文字的画面 |

## 共用的出片办法

三条线都是一个网页：页面暴露 `window.renderAt(t)`（画出第 t 秒）、`window.DUR`（全片秒数），准备好以后设 `window.ready = true`，出错设 `window.fatal`。出片脚本用无头浏览器逐帧截图再编码。

```bash
# 一次性安装（在工作目录；会下载一个约 150 MB 的浏览器，先告诉用户）
npm install playwright
npx playwright install chromium
npm install three                      # 只有 three.js 那条要

# 把最小工程复制到工作目录再改，不要直接改技能目录里的
node "SKILL/scripts/browser-render.mjs" 我的片子 --stills 0,2.5,5     # 先出几张静帧看
node "SKILL/scripts/browser-render.mjs" 我的片子 --out 我的片子/out/film.mp4 --audio 音轨.wav
```

脚本会在页面报错、请求了外部地址时停下并说明原因。

## 都要守的做法

1. 画面只由时刻决定。`renderAt(t)` 不读系统时间，不用 `Math.random()`，不依赖上一帧；随机数从整数种子算。这样才能单独重出某一帧、分段续跑、两次出来一样。
2. 先定速度再排镜头。让一拍是整数帧（30 帧每秒时：120 拍每分钟一拍 15 帧，100 是 18 帧，90 是 20 帧，72 是 25 帧），镜头的切点放在拍子上，配乐和画面才对得齐。
3. 先写镜头表再写代码：每个镜头的起止时刻、景别、镜头怎么动、画面里发生什么、配什么声音。
4. 先做最没把握的那一个镜头的静帧，成立了再铺开。
5. 出全片之前，把每个镜头的第一帧和最后一帧并排看。两张几乎一样，说明这个镜头里什么都没动，先改。
6. 切镜头的那一帧，新镜头里要紧的东西已经在画面里了。
7. 每一轮都出静帧自己看，再出每秒一格的总览图。看不了图就没法做这三条线。

## Canvas 2D 短片

- 分两层：工具（种子随机、缓动、关键帧取值、出帧）可以沿用；角色、场景、画法每支片子现写。
- 角色先单独画出来看：几种眼睛、嘴、姿势排成一张角色卡。
- 表演写成关键帧表（时刻、数值、缓动）。起跳前先压扁，空中拉长，落地再压扁；表情变化时身体先停一下。
- 手绘感的抖动每秒换 7 到 8 次。每帧都换会读成噪点。
- 画面事件（落地、碰撞、关门）登记成一张表（最小工程里的 `EVENTS`），音效的时刻从这张表取。
- 每帧开头把画布的变换、透明度、混合模式重设一遍。
- 常见的毛病：角色在全景里太小（让镜头跟着推近）；脸被前景的道具挡住（出全片后专门看一遍脸）。

## three.js 场景

- 默认的材质和灯光出来偏平、偏塑料。画质靠每帧多次采样累加（最小工程里的循环）：每次换子像素偏移和快门内的时刻，出抗锯齿和运动模糊；再抖镜头在光圈上的位置出景深，抖灯的位置出软阴影。
- 最后画到屏幕的那一遍要自己做色调映射和伽马（最小工程里的 `fin`），否则画面发暗。
- 表面的质感按世界坐标程序生成（几个尺度的噪声叠起来），不靠贴图。
- 每个镜头至少有一样东西在动，不能只有镜头在慢慢推。
- 写实的场景里该有人的地方没有人，会被看成模型摆拍。做不了写实的人物时，选不需要人的题材，或者告诉用户这个短处。
- 两个面重合会闪：贴着别的面的薄件错开几毫米。
- 采样数：试帧 4 次，出片 16 到 48 次。先用几帧量出每帧多久，算好总时间再出全片。

## 全屏着色器

- 整幅画面是一张全屏的片元着色器：每个像素发一条视线，沿着它一步步走，碰到地形就算颜色。`gl.js` 是管道（多次采样累加、调色输出、噪声），`scene.glsl` 是场景，只要写一个 `scene(ro, rd, px)` 函数。
- 太阳的位置、雾的浓度这类参数从时间线传进着色器（`uP0`、`uP1`），不写死。同一个世界换参数和机位就是另一个镜头。
- 多个镜头时，运动模糊的子采样不要跨镜头：每帧先定它属于哪个镜头。否则切点那一帧是两个画面的叠影。
- 机位要一直在地形和云层的外面，否则整屏一片灰。
- 远处的雾用不带太阳的天空底色。用带太阳的，太阳下方会出一道光柱。
- 云、水、雪这类每样都要另写一段算法，一次加一样，加一样看一次图。
- 每帧采样数 8 到 16。有体积云时每帧要一秒左右，先量再出全片。

## 声音

三条线自己不出声音。可以借主生产线的合成器（`SKILL/scripts/engine/synth.mjs` 的 `Music` 类和 `sfxSignal`，用法看 `SKILL/scripts/engine/music.mjs`）按拍子写一段配乐，存成 WAV，再用 `--audio` 交给出片脚本。没有声音的片子要告诉用户。
