# 用实拍素材，导出剪辑工程

两件事：把用户已有的视频（实拍、录屏、别处导出的片子）的一段放进片子里；把出好的片子导出成 Final Cut Pro 和剪映能打开的工程，让人接着剪。

## 把素材的一段放进片子：`clip` 版式

`video.json` 里加一场 `clip`，和别的版式混着排。整支片子全是 `clip` 也可以，那就是在剪辑已有素材。

```json
{ "layout": "clip", "file": "素材/采访.mp4", "from": 12.4, "to": 18.0, "say": "这一场的字幕" }
```

| 字段 | 说明 |
|---|---|
| `file`* | 素材文件，相对 `video.json` 的路径。原文件不会被改动 |
| `from`、`to` | 取素材里第几秒到第几秒。不写 `from` 从头取，不写 `to` 取到结尾。这一场的长度就是 `to - from` |
| `fit` | `"cover"`（默认）铺满画面，硬切进来；`"contain"` 完整放在画面中间，四周是主题的背景 |
| `volume` | 素材原声的音量，0 到 2，默认 1；`0` 静音。原声响的时候配乐自动压低 |
| `title` | 左上角的一个小角标（人名、地点、出处） |
| `say` | 字幕，和别的版式一样 |

- 全片只要素材的原声、不要配乐：最外层写 `"music": false`。
- 有 `clip` 的片子最多 60 场。
- 风格包的外框、角标、转场会照常加在素材上（例如 `news` 的标题条压在画面下方）。

### 先看素材，再定取哪一段

你看不了视频，但能看图。对每条素材跑一次：

```bash
node "SKILL/scripts/footage.mjs" 素材/采访.mp4                    # 整条：规格、静音的位置、一张带时间的胶片图
node "SKILL/scripts/footage.mjs" 素材/采访.mp4 --from 30 --to 60  # 某一段看细一点
```

打开它出的胶片图，每一格左上角是素材里的秒数。`from`、`to` 按这个定。

- 有人说话的素材：剪口放在它列出的静音里，不要切在一句话中间。用户给了逐句的文字稿（带时间的 `.srt`）就按文字稿定；没有的，你只能凭静音和画面估，回报时说明哪几处拿不准。
- 你看不了的：说的是什么、语气对不对、动作有没有被切断。这些请用户看一遍成片。
- 删掉什么、留下什么，回报时逐条列出来（从第几秒到第几秒、为什么）。

## 导出能接着剪的工程：`--project`

```bash
node "SKILL/scripts/make.mjs" 片名/video.json --project
```

出完成片以后，在 `片名/out/project/` 里多出：

| 文件 | 给谁 |
|---|---|
| `片名.fcpxml` | Final Cut Pro：菜单「文件 > 导入 > XML…」。DaVinci Resolve 也能导入这种文件 |
| `剪映草稿/片名/` | 剪映专业版：把整个文件夹复制到剪映的草稿目录，重开剪映 |
| `片名.srt` | 字幕文件，别的剪辑软件用 |
| `media/` | 每一场一个不带字幕的视频文件，配乐、音效、人声各一个文件 |

工程里的时间线：每一场是主轨上的一个片段；配乐、音效、人声各一轨；字幕是能改字的文字。`clip` 场直接引用素材原文件，取的范围就是 `from` 到 `to`，在剪辑软件里可以再往两头拉。

告诉用户这几件事：

1. 工程里写的是绝对路径。文件夹挪了位置、换了机器，要在剪辑软件里重新链接素材。
2. 剪映打开草稿后会把它改成自己的格式，脚本就改不了这一份了。要改内容，改 `video.json` 重新导出，当成一份新草稿。
3. 剪映草稿的格式没有公开说明，剪映升级后可能打不开。脚本只写了最基本的片段、声音和字幕，不带转场和特效。
4. 成片里配乐在人声响起时会自动压低；工程里的配乐是一整条，没有压低，要在剪辑软件里自己调。
5. `clip` 场上的角标和风格包压在素材上的装饰不带进工程。
6. 导出时自己核对帧率和采样率（剪映的导出对话框默认值可能和工程不一样）。

脚本会核对工程引用的文件是不是都在，报告里有一行 `[通过]` 或 `[问题]`。工程能不能在剪辑软件里正常打开，脚本查不了，请用户打开看一眼。
